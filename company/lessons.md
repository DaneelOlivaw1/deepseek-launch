## 关键教训

## Wave 003 Lesson — 目标用户定义必须在任务中明确约束

**之前认为:** Employee 会自动理解目标用户是"国际非技术用户"，推广时会选择合适的社区。

**现在认为:** Employee（DeepSeek V4 Flash）在没有明确约束的情况下，默认倾向中文社区（可能因为 DeepSeek 是国产模型的中文关联）。目标用户的定义（"国际用户，非技术，英语社区"）必须作为硬约束写入任务描述。

**触发数据:** Wave 003 的 3 篇推广文案中，2 篇面向 V2EX 和知乎（中文社区），只有 1 篇面向 Reddit（英文社区）。而 Landing Page 全部是英文，目标用户明确是国际用户。

**教训:** 任务中的"目标用户"描述必须带排除项。例如："目标社区：Reddit 英文子版（不是 V2EX，不是知乎，不是任何中文社区）。确认：页面是英文，用户是老外。"

## Wave 003-B Lesson — Landing Page 承诺必须与可交付产品一致

**之前认为:** Landing Page 是验证工具，可以写理想化的产品愿景（"数据留在本地""离线模式"）来测试需求，实际产品可以在验证后调整。

**现在认为:** Landing Page 的承诺必须是我们能实际交付的 MVP 的真实描述。用"本地隐私"吸引来的用户，在发现产品是云 API 封装后会成为最愤怒的批评者。这不仅是不道德的，而且会污染实验数据——你不知道用户是为"隐私"还是为"简单"注册的。

**触发数据:** CEO 在推广前的最终审查中发现：index.html 声称 "Your Data Stays on Your Device""Offline Mode""never uploaded to the cloud"，但最可行的 MVP 架构（DeepSeek API 封装）会将所有对话发送到云端服务器处理。

**教训:** 
1. 每一条 Landing Page 声明都必须可追溯到 MVP 架构中的一个实现路径。如果找不到实现路径，删除该声明。
2. 在向真实用户推广之前，CEO 必须逐条审核 Landing Page 声明的真实性。
3. "先画大饼再调整"在创业中可能适用，但不能在面向终端用户的产品声明中适用——尤其当目标社区（r/privacy, HN）有极高的谎言检测能力时。

## Wave 003-C Lesson — Employee 能执行任务但不会质疑任务前提

**之前认为:** Employee 在执行任务时会发现并报告产品逻辑中的矛盾（如："页面说本地运行，但产品是 API 封装"）。

**现在认为:** Employee 按照任务描述机械执行。Task #4 要求"翻译 Landing Page"，Employee 忠实地翻译了所有声明——包括那些在技术上不可行的声明（local storage, offline mode）。质疑任务前提是 CEO 的职责，不是 Employee 的。

**触发数据:** Task #3 和 Task #4 都涉及 Landing Page。Employee 改进了表单和语言，但没有一条报告提到"页面声称本地运行，但我们的产品很可能是 API 封装，这存在矛盾"。

**教训:** CEO 不能指望 Employee 做战略性质检。在向 Employee 布置涉及产品声明的任务之前，CEO 必须先验证声明的真实性。Employee 是执行者，不是挑战者。

## 认知变化

**H002 认知（未更新——无数据）:** 尚不知道 Landing Page 是否能吸引 ≥10 个邮箱注册。

**新认知 — 价值主张优先级:** "简单易用"（一键安装、无需配置）可能是比"本地隐私"更真实且同样有效的价值主张。ChatGPT Desktop 的成功证明了"让 AI 变简单"本身就是付费价值。

**新认知 — Employee 能力边界:** Employee 善于执行明确的技术任务，但不会质疑产品假设。战略一致性检查必须在 CEO 层面完成。
